## Summary

**In plain terms:** [project-management:DEC-052](../../../.pkit/capabilities/project-management/decisions/DEC-052-comment-house-style.md) decided *what* every comment the pm capability posts carries and how it reads — the boundary rule, the two content categories, the per-kind frame (marker + provenance footer), and the house style. It deferred *how the string is composed*. This contract says: every place that posts a pkit comment hands **structured data** (the comment kind plus its payload fields) to **one shared renderer**, which writes every byte of the result — icons, layout, marker, footer. No poster ever concatenates comment markup by hand. Because producers pass *data* and never *text*, the house style is enforced at one construction point instead of trusted at N call sites, and the machine-critical parts of a comment (its kind marker, its verdict line) are emitted to schema-owned formats that a `parse(render(x)) == x` round-trip test pins — so the read side (the merge gate, the freeform spoof guard, hook idempotency) can recover them from the posted text without the renderer and the parser drifting apart.

This is the fourth member of the capability's seam family — after the label read-path contract [ADR-026](ADR-026-substrate-map-read-path-contract.md), the non-label substrate-write contract [ADR-031](ADR-031-substrate-write-path-contract.md), and the provenance-footer seam [ADR-037](ADR-037-provenance-write-path-contract.md) — and inherits their sole-constructor-plus-guard shape. What makes it its own record is a *different* boundary from ADR-037's — lateral, not a harder version of the same one. ADR-037 protects a script-owned *region inside a body the agent rewrites*; here the producer never authors comment text at all — the whole artifact is a pure **data → string** composition — and the read side must recover a **positive value** from the result (the verdict word the merge gate parses), where ADR-037's read side only needs its footer region to stay **inert** (unmisread by body validators).

## Context

DEC-052 fixed the content-and-style model for every comment the pm capability posts and explicitly scoped out the render seam. Today each poster builds its own string: the audit/override step, the filing helper, the move step, the review-verdict step, and the freeform/hook pass-through each concatenate icons, body text, a marker, and a footer inline. That is the same pre-contract convergence surface the earlier seam members faced — an enumerable set of construction points that must converge on one primitive for a whole-artifact invariant to hold. There is no single comment-construction chokepoint today.

Two properties DEC-052 and the sibling review feature require cannot hold while each poster hand-builds its string:

1. **The house style is only as consistent as the least careful call site.** DEC-052's frame (per-kind marker + universal footer) and its boundary rule are aspirational if N posters each reproduce them; one poster that forgets the footer, or repeats the `🧰` mark on the payload line, drifts silently — the same drift that prompted DEC-052.
2. **The comment must be machine-recoverable.** Several readers parse pkit comments back: the merge gate reads a review verdict from the comment's verdict line (the [project-management:DEC-028](../../../.pkit/capabilities/project-management/decisions/DEC-028-agent-as-approver-paths.md) grammar); the [project-management:DEC-047](../../../.pkit/capabilities/project-management/decisions/DEC-047-freeform-comment-verb.md) spoof guard co-reads that same grammar to reject a forged verdict — a *fail-open* reader, where a miss lets an approval be forged; and the freeform/hook kinds are identified, and hook idempotency keyed, off the `<!-- pkit-<kind> -->` / `<!-- pkit-hook: <id> -->` markers. A rendered comment whose marker or verdict line a parser cannot recover breaks those readers, and a hand-built comment has no guarantee its emitted marker and verdict line match what they expect. (Provenance is *not* in this set — the canonical audit trail is the engine journal, and `pkit pm history --check-drift` diffs that journal against the GitHub timeline; the comment footer is a static, human-facing stamp nothing parses back.)

The review sibling (#795) additionally needs to build against this seam *before* the general renderer is complete — it ships a temporary formatter behind the same `format(data) → string` interface — so the boundary must be a named contract, not an incidental function.

## Decision

1. **One sole-constructor render seam.** A single `_lib` module — the comment renderer — is the only place a pkit-authored comment string is constructed. Every poster obtains its posted text by handing the renderer **structured data** and posting what it returns; no poster concatenates comment markup (icons, layout, marker, footer) inline. This is ADR-026's sole-constructor instinct and ADR-031's single-construction-point, applied to the whole comment rather than a region of a body.

2. **The seam interface is `format(data) → string`.** The renderer takes structured data — the comment **kind** plus that kind's payload fields — and returns the final string; producers (review agents, the audit/move steps, hooks) hand over *data* and the renderer writes every character. The interface is the decoupling contract: a second producer can build against `format(data) → string` and ship a temporary formatter behind it without waiting on the general renderer (the review feature's need), and the general renderer can restyle freely behind the interface without touching producers. This is the core principle one altitude up from ADR-037's *the agent never owns the footer bytes* — here the producer never owns the comment bytes at all.

3. **Home: the pm capability's `_lib` (e.g. `comment_render.py`); hoist only on a written trigger.** The renderer lives with its one code consumer — the pm capability — not at the shared/backbone tier. The software-engineering capability ships prompts, not scripts, so it consumes the *contract*, not the *function*; there is one code consumer today. **The hoist trigger, written down so it is not a judgement call later:** move the renderer to a shared backbone home the day a *second capability ships code that renders a pkit comment*, revisiting the code-home boundary the permission core set as precedent [ADR-003](ADR-003-permission-core-code-home.md) at that point. Until then, hoisting is speculative generality.

4. **Style storage is two layers, each owning a distinct job.** (a) A small **schema** (`comment-style.yaml`) owns the vocabulary and every machine-load-bearing format — the per-kind `<!-- pkit-<kind> -->` markers, the section labels, the verdict→glyph map, the **verdict-header contract**, and DEC-052's schema-owned per-kind decorative icons — drift-guarded against the code that reads them (the read-side-validator pattern the integration marker established). (b) **Code** owns everything else: reading the vocabulary from the schema, assembling the string, laying out the human structure, deriving computed values once, and placing the machine-critical parts per the schema contract. The dividing rule: **the schema owns every token and every format a reader parses; code owns assembly and layout.** There is deliberately **no template layer** — the human layout lives in code, which is directly testable, and no third-party templating-engine dependency is added to the otherwise-lean comment-posting scripts. The one line where the human and machine surfaces coincide is the **verdict header**: under the gate-parser design #795 ratifies (this record's acceptance is sequenced behind it — see Implications), the merge gate reads the *human-visible* header itself (anchored on the verdict word), so that line is both the most prominent presentational element and the gate's anchor. The rule resolves the coincidence to the schema — the verdict header is a **schema-owned contract line** that code places — so restyling it is a schema change the round-trip test (item 6) guards, not a casual code edit that could silently break the gate (the ownership hazard ADR-037 exists to remove). *(The concrete token set is the schema's content, not pinned here; DEC-052 pins which glyphs are record-level semantic anchors versus schema-owned decoration.)*

5. **The footer is delegated to the provenance helper; on a comment it is exactly-one by construction, and pass-through kinds are append-only.** The renderer does not reimplement the footer — it calls the provenance module's **byte-producing** footer helper (`render_footer`, the non-stripping entry point, *not* the strip-then-append `stamp` seam ADR-037 uses for bodies) for the footer bytes. Because a comment is **constructed once and never edited** (unlike a body, which is rewritten), *exactly one footer* holds **by construction** — a stronger guarantee than the body path's strip-then-append, which exists precisely because bodies are rewritten. This is the constructed-vs-edited distinction DEC-052 drew: the comment footer is a **static, write-once** stamp; ADR-037's body footer is self-replacing. **One hazard is load-bearing:** the footer helper's strip-to-end-of-document must **never** run over a *pass-through* comment (freeform, hook) carrying a user's or adopter's words — a pasted footer sentinel in that text would make a strip silently delete everything after it. Pass-through kinds are therefore **append-only**: the renderer frames the untouched payload and appends one footer, and never strips. This realises DEC-052's rule that pass-through payloads are framed but never restyled.

6. **The machine-critical parts round-trip: `parse(render(x)) == x`, guarded by a test.** The renderer emits each comment's machine-recoverable parts to **schema-owned formats** such that every read-side parser recovers them from the posted text: the **marker family** — the per-kind `<!-- pkit-<kind> -->` marker (→ kind) and any id it carries (e.g. `<!-- pkit-hook: <id> -->` → the hook idempotency key) — and, for a verdict, the **verdict-header contract** that both the merge gate and the DEC-047 spoof guard read. A `parse(render(x)) == x` round-trip test over those formats pins the renderer and every read-side parser together so they cannot drift — a drift that fails *open* for the spoof guard (a forged verdict slips through), which is what earns the test its place. **Scope: the invariant binds the machine-load-bearing projection, not the whole human-facing string** — the decorative prose (section bodies, glosses) stays free to restyle; only the marker family and the verdict-header contract must survive render→parse. Provenance is deliberately *not* in scope: nothing parses the comment footer back (item 2). Overclaiming a byte-exact whole-comment round-trip would forbid the restyling the seam exists to allow.

7. **A guard test proves no comment is composed outside the seam.** A grep/AST guard over the comment-posting scripts asserts that none constructs a pkit comment string (a `gh issue comment` / `gh pr comment` body, or the native review-body equivalent) outside the renderer's call path. This is the second half of the family's construction-test-plus-guard split: the round-trip test (item 6) proves the renderer builds the machine-critical parts correctly; the guard proves the renderer is the *only* builder. Both ship together, as in ADR-026/031/037.

## Rationale

**Why a pure data → string seam rather than shared string helpers.** Helpers a poster calls to "build a footer" or "add a marker" leave the poster in charge of assembly — and therefore in charge of getting the house style and the machine markers right N times. Handing the renderer structured data and letting it write every byte moves both the house style and machine-recoverability from *trusted at each call site* to *guaranteed at one construction point*. This is the escalation ADR-037 made for the footer region, taken one level up to the whole comment: there, the agent could still mangle a region it was handed; here, the producer is never handed comment text at all.

**Why this is a record distinct from ADR-037.** ADR-037's boundary is a script-owned region inside a body an agent rewrites; its whole difficulty is surviving the agent's edits to surrounding text. This seam's boundary is lateral, not harder: the producer authors *no* comment text at all (a pure data → string composition), so the agent-edit hazard is absent — but a new requirement takes its place. ADR-037's footer is read back only to be found **inert** (its item 5 keeps an un-stripped footer from being misread by body validators); ADR-054's comment is read back to recover a **positive value** — the verdict word the merge gate and the DEC-047 spoof guard parse — which is why the round-trip invariant (item 6) is load-bearing here and only an inertness constraint there. Folding this into ADR-037 would bury a different boundary and a different read-back obligation under a contract that shares neither. Pinning it as the family's fourth member, citing the first three as the inherited sole-constructor-plus-guard pattern, keeps each record about one boundary — mirroring how ADR-037 split from ADR-031 rather than extending it.

**Why the round-trip is scoped to the machine-load-bearing parts.** A whole-comment `parse(render(x)) == x` would make every decorative choice a parser obligation and freeze the human layout the house style is meant to keep evolving. Binding the invariant to only the marker and the schema-owned contract lines gives the read side everything it needs — kind, hook id, gate signal — while leaving the prose free, the same separation DEC-052 drew between the machine frame and the human payload.

### Alternatives considered

- **Shared formatting helpers, posters keep assembly.** Rejected — it re-creates the drift the seam exists to remove: the house style and the machine markers stay only as consistent as the least careful poster, exactly the failure ADR-026/031/037 converged their construction points to prevent.
- **Hoist the renderer to the shared/backbone tier now.** Rejected as speculative generality — one code consumer today (pm); the software-engineering capability consumes the contract, not the function. The written hoist trigger (item 3) fires the day a second capability renders a comment in code, revisiting that code-home boundary [ADR-003](ADR-003-permission-core-code-home.md) then. Choosing the shared home before the second consumer exists would guess at requirements it does not yet have.
- **Byte-exact whole-comment round-trip.** Rejected — it would forbid restyling the human layout, defeating the seam's purpose; the read side needs only the machine-critical projection (item 6).
- **A template layer for the human layout** (schema tokens + a template file + code assembly — the three-layer shape earlier weighed). Rejected, matching the architect exploration's finding: a template engine is a new third-party dependency spread across every otherwise-lean comment-posting script, and template-embedded logic is untestable, while the payoff — layout evolving without code edits — is thin against only a handful of rarely-changing kinds, for which a code edit is cheap. The visual-review need the template layer was meant to serve is met instead by the generated gallery (Implications) — the *real* rendered output under change control, not template source hoped to render right. The accepted shape is schema-owned vocabulary + code-owned assembly and layout; the exploration's ownership objection (machine markers becoming a layout author's responsibility) is moot, since no machine-load-bearing line lives outside the schema.
- **Fold the render seam into DEC-052.** Rejected at DEC-052 authoring time — the content/style model is capability-internal (a DEC), while the composition mechanism is a project-architectural contract shared with the review feature and the merge gate (an ADR); the same content-vs-mechanism split DEC-041 and ADR-037 drew.

## Implications

- **The comment renderer is authored at implementation time**, once this record is accepted — the sole constructor of pkit-authored comment strings, exposing `format(data) → string`, delegating the footer to the provenance module (ADR-037), and reading its tokens and markers from `comment-style.yaml`.
- **The comment posters converge** on the renderer for their posted text; the guard test lands with them. The enumerable poster set is the convergence surface — adding a future poster means routing it through the seam or failing the guard.
- **Existing comment-format homes converge onto the seam.** This is not greenfield: the audit-comment template lives today in `validation-severity.yaml`'s `audit_comment_template` (read by `move-issue`), and marker literals are scattered across `_lib` (`agent_verdicts`, `comment`, `move-issue`). For item 1's sole-constructor claim to hold, these converge — the audit comment renders through the seam and its tokens/markers move into `comment-style.yaml` (or become cross-references) — so the guard (item 7) is never left green while a poster still formats a comment partly outside the renderer. DEC-049 already fought this two-sources-for-one-string battle; the seam keeps that win.
- **`comment-style.yaml` is authored via the schema skill** (citing DEC-052), carrying the tokens, the per-kind markers, the verdict→glyph map, and the **kind roster** (each kind plus its off-surface-payload descriptor, which DEC-052 delegates to the schema as evolving inventory), drift-guarded against the renderer and the read-side parser. It is additive schema content (no `schema_version` bump, no migration).
- **The seam enables a committed comment gallery kept as a snapshot test.** Because the renderer is a pure `format(data) → string`, a fixed set of *frozen* sample inputs (fixed versions, dates, issue numbers) renders to a set of golden Markdown files committed to the repo. One snapshot test both **renders** them (in its update mode) and **checks** them (by default, in CI), so any change to the renderer or `comment-style.yaml` that alters a comment's output surfaces as a failing test and a reviewable diff in the PR — seen by a human and the `readability-reviewer` before it ships. This is the visual-review surface the dropped template layer would have served, but as verified output rather than hoped-for source, and it retires the hand-authored rendered-example note (which can silently drift). It complements the round-trip test (item 6): the round-trip guards the machine-recoverable projection; the gallery guards the whole human-visible surface against unseen change. The snapshot tooling and the sample-data set are implementation detail (an issue under the EPIC), not pinned here.
- **The review sibling (#795) builds against `format(data) → string`** and ships a temporary formatter behind it (its home is #795's to choose on the pm side, since the software-engineering capability ships no scripts), so it is not blocked on the general renderer; the verdict line it and the merge gate depend on is the schema-owned contract the round-trip test pins. The DEC-028 / [ADR-042](ADR-042-verdict-selector-strict-gate.md) verdict-grammar changes that consume this are #795's, coordinated through this interface, not pinned here. The guard (item 7) cannot go green until #795 routes the verdict poster — today `review-pr` splices the reviewer agent's raw stdout, so the agent still owns comment bytes below line 1 — through the seam: a cross-feature ordering coupling, since by the family's own logic a partial convergence is a guard that cannot yet be written.
- **Pass-through kinds are append-only** at the renderer (item 5) — neither the renderer nor the guard may route a freeform/hook payload through any strip-to-end path.
- **Acceptance is sequenced behind #795.** Item 4's premise — that the merge gate reads the *human-visible* verdict header — is #795's gate-parser design (its DEC-028 / [ADR-042](ADR-042-verdict-selector-strict-gate.md) amendment), not this ADR's to ratify. This record is therefore accepted only once that amendment lands, at which point item 4 and the verdict-header contract cite it; until then ADR-054 stays `proposed`. The seam decisions (items 1/2/3/5/7) do not depend on that premise — only item 4's verdict-header rationale does — so nothing else in the contract is contingent on the sequencing.
- **Accepted by the maintainer before the trunk implementation builds against it** (per [PRJ-005](../../../.pkit/decisions/project/PRJ-005-adopt-adrs.md)) — a forward design contract, not self-accepted. The renderer, the converged posters, the `comment-style.yaml` schema entry, the round-trip test, and the guard land citing this record once it is accepted.
- **This ADR pins the contract, not the comment UX.** What each comment carries and how it reads are DEC-052's; the concrete tokens are the schema's. On-call/maintainer reference: if a posted comment drops the footer, doubles the `🧰` mark, or a gate cannot read a verdict back, the seam or the guard has been bypassed — check that first.
