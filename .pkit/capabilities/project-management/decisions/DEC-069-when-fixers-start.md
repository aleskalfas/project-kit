**In plain terms:** a fixer's run takes the confined form DEC-056 decides wherever that form is built and the harness holds it. Where it does not, the drift command starts a fixer only where a person runs the command at a terminal and watches, or where the person turned on a switch of the project's. Such a run takes the unconfined form, as a reviewer's run does, under the person's and the project's settings, in a clone of the repository at the pinned commit of the default branch. Otherwise the command starts no fixer, and lists what went stale with the command to run. For example, while no harness holds the confined form, the project manager's run after a merge prints each stale page and `pkit pm fix-drift`, and the person runs that command at a terminal and sees each fixer start and end.

## Context

[project-management:DEC-056-drift-fixers] decides that each fixer's run is confined (point 5), and that a harness unable to confine a run starts no fixer (its Rationale, "Fail closed"). It rejects having the person run the command each time, since nothing would then run after a merge. The probe of [pkit:ADR-066] point 12 found that Claude Code 2.1.310 cannot hold the confined form. With its scrub of credential variables on, it forced the run out of the mode that refuses without asking, and it loaded three plugins the run's settings did not name ([project-kit#2225](https://github.com/aleskalfas/project-kit/issues/2225)). So under DEC-056 no fixer starts on that harness.

The maintainer chose:
- **27 October 2026,** on [project-kit#2234](https://github.com/aleskalfas/project-kit/issues/2234): "b", fixers on request, watched, nothing unattended for now.
- **11 November 2026:** an agent a command starts in its unconfined form is to refuse settings that approve calls without asking. [project-kit#3041](https://github.com/aleskalfas/project-kit/issues/3041) is to build that refusal, and the record it rests on decides which modes count.
- **12 November 2026,** on #2234, of runs nobody watches: "I think that should be possible at some moment to switch it on to run it automatically like review panel. I don't want to change decision then." Asked whether a record should decide that switch now, he answered "yes rework the dec".

Terms:
- A run is *watched* where a person started the drift command at a terminal: its standard input and its standard output are both terminals, the test by which the drift command asks the fixers question (DEC-056 point 2).
- A run's *unconfined* and *confined* forms are the agent runner's two forms ([pkit:ADR-066] points 3 and 10).
- The confined form *holds* a run where that form is built and the harness and the platform can hold it for the run.

## Decision

**A fixer's run takes the confined form wherever that form holds it, and otherwise the unconfined form in a clone at the pinned commit, which starts only where a person started the drift command at a terminal or turned on the project's switch.**

### 1. A person starts the fixers at a terminal

- **Where the confined form does not hold a fixer's run (point 2), the drift command starts that fixer only in a watched run, or where the switch of point 4 is on.**
- **With nobody at a terminal and the switch off,** as in the project manager's run after a merge, it starts none of those fixers. It lists each stale artefact one of them would take, with its fixer, and the command a person runs at a terminal to start them. Where it starts no fixer at all, it takes no lock and writes nothing.

### 2. A run is confined where that form holds it, and otherwise unconfined in a clone at the pinned commit

- **Confined where that form holds it.** A fixer's run, watched or not, takes the confined form of DEC-056 point 5 wherever that form holds it.
- **Unconfined otherwise.** A watched run takes the unconfined form, and a run nobody watches takes it only where the switch of point 4 is on.
- **The fallback is for the harness alone.** A run falls back to the unconfined form only where the harness or the platform cannot hold the confined form. Where the run's own inputs fail the confined form, such as its definition, its clone or the project's denies, it starts in neither form, and is reported. [pkit:ADR-066] sorts each cause of a refusal (its point 2). A start report that does not match the run's settings ends the run, which then starts in neither form (its point 9).

An unconfined run:
- **Works in a clone at the pinned commit.** It takes the form the review command's runs take ([pkit:ADR-066] point 10), in a clone of the repository at the commit DEC-056 point 3 pins, never in the person's checkout. It takes the project's settings at that commit and the person's own: their user settings and their checkout's local settings. The clone is not provisioned as a confined run's is, since the run's commands share the person's tools and network, as a session of theirs does. No flag that bypasses the permission rules is passed.
- **Takes the mode [pkit:ADR-066] point 10 gives an unconfined run,** as a review's run does. So the refusal the record of #3041 decides reaches it with no change to this record.
- **Is announced in a watched run.** Before the first fixer starts, the command says that the fixers run under those settings, and how to stop the run.
- **Has a brief that says whether a person watches the run,** names no temp folder, and tells the fixer to propose only: to keep to the command forms the run's rules allow (DEC-056 point 5), write nothing outside its workspace and run no writer. Those settings, not the run's rules, hold what it may do.
- **Runs the definition at the pinned commit** (DEC-056 point 3), and is refused where it cannot. [pkit:ADR-066] points 1 and 10 say how.
- **Hands its files to the queue through a guarded copy,** and an entry the copy refuses sets the fixer's proposals aside, as a breach does (DEC-056 point 5).
- **Held as a leaf where the command can.** The command starts no fixer whose definition grants a tool that starts agents (DEC-056 point 1), and refuses to start inside a fixer's run.
- **Counts a call its settings stopped as `refused`** (DEC-056 point 3), and those settings join the setup. The command does not read them, so a `none` they caused stands until the person forces the artefact's dispatch.

### 3. A grant counts for every watched run

- **The question** says when the agent starts and under whose settings, as points 1 and 2 decide. It and the grant command's words say that a grant also starts the fixer after each merge, with nobody watching: confined, once the harness holds the confined form, and unconfined where the switch is on.
- **Every grant counts for a watched run,** whether the person answered the question or ran the grant command, which shows no question.
- **Toward a run nobody watches,** a grant counts only where the question it answered said so: for the confined form as DEC-056 point 2 decides, and for the unconfined form only where the switch is on. A grant given under earlier words counts for watched runs, and for others once the person answers the question again.

### 4. A switch of the project's lets an unconfined run start with nobody watching

- **Off by default.**
- **The person's to turn on.** The switch is a setting of this capability's project configuration. Only a change of the project's that the person authorises turns it on, and no install, upgrade or migration does.
- **On from the default branch, off at once.** Turning it on counts only from the default branch, at the commit the drift command's run is pinned to, as a grant does (DEC-056 point 2). Turning it off counts at once, from the default branch, or from this capability's project configuration as a working tree holds it, committed or not: the working tree of the checkout the run starts from, or the main working tree, where the queue lives (DEC-056 point 6).
- **Held at every merge.** Each command of this capability that merges a change into the default branch holds a change that turns the switch on until the person authorises that merge themselves, which an authorisation of merges given up front does not cover. The hold says in plain words what turning the switch on means, and lists the fixers already granted. While the switch is on, each holds a change to the grant list the same way, and shows which fixers it grants. A change that turns the switch off is not held.
- **Turning it on is the consent** to unconfined runs nobody watches, for each fixer the project granted then or grants later.
- **With several people.** Turning the switch on consents for every person whose session runs the drift command, each such run under that person's own settings and credentials, beside the project's settings at the pinned commit. Each person turns it off for their own runs at once, from their own configuration.
- **An unconfined run nobody watches keeps point 2's rules,** save what a person watching sees. Every run keeps the bounds of DEC-056 point 4.
- **Reports wait where the person meets them.** In a run nobody watches, the faults of the setup (DEC-056 point 3), the failures (DEC-056 point 4) and a refused copy (point 2) are written to the queue's index and to the count line the landing command shows (DEC-056 point 6, "Visible"). Each such run records there which form it took, or that neither started it.

### 5. What stays open is stated

As intent the harness cannot enforce is (COR-028 point 3):
- **An unconfined run** may do whatever its settings let a session do, such as writing outside its workspace, reaching the network, pushing, merging, changing a record's status, running a writer, or starting the harness from its shell. Nothing checks what it changed outside its workspace. A person watching sees which fixers start and how each ends, not each call, and nobody sees a run the switch starts.
- **The tool list.** The leaf rule, and much of what bounds an unconfined run, assume that the tools a fixer's definition lists bound its session, which [pkit:ADR-066] point 12 lists as unconfirmed.
- **A terminal tells that one is attached,** not that a person watches. A harness whose shell gives a command a terminal, or an agent that fakes one, can start fixers nobody watches. Only the permission layer can stop such a call, in a mode that asks about a call no rule allows, and no rule this capability ships names one.
- **What the hold covers.** It covers the switch and the grant list, not what else shapes an unconfined run nobody watches: a granted fixer's definition, the project's settings, the instructions and rules the harness loads in the clone, and the permission hook's default agent. A merged change to any of them reaches the next such run unheld.
- **Merges the hold does not see.** A direct commit to the default branch passes no merge, so nothing holds it, and only the commit's author vouches that the person turned the switch on. Nor is a merge held that passes outside this capability's commands, such as a host's merge button, its auto-merge, or `gh pr merge` run by an agent. Inside a command, only a prompt at a terminal tells that the person authorised the merge themselves, and an agent can fake a terminal.
- **Where a run nobody watches runs.** Beside the project manager's session after a merge (DEC-056 point 3), this record names no runner of the drift command with nobody at a terminal. A continuous-integration run takes that system's settings and token, and its queue is lost with its clone.
- **Causes not yet sorted.** [pkit:ADR-066] point 2 lists every cause for which a confined run is refused as one the harness cannot confine, and does not yet sort which are the harness's or the platform's and which the run's own, such as settings that fail the harness's schema. Until it sorts a cause, only point 2's principle holds the fallback for it.
- **A proposal's words and a pull request's text** stay open as for a confined run (DEC-056 point 5).

## Rationale

**Point 1, a person at a terminal.** Where the confined form does not hold, a fixer runs in the unconfined form or not at all. A person who runs the command at a terminal starts each run by their own act, sees which fixers start and how each ends, and can stop the run. The debt does not wait for someone to read the check, since the project manager's run after each merge lists it with the command to run. A terminal is the test the fixers question already reads. It tells that a terminal is attached, which an agent's session lacks unless it fakes one (point 5). A flag every agent can pass tells nothing until a rule denies it to agents.

**Point 2, confined where it holds, the reviewers' form otherwise.** Confining narrows what a run may do, so it needs no consent and no later decision. The review command's reviewers run in the unconfined form under the person's settings, so the runner keeps two forms, not three. A fixer still widens what runs, so the person grants it first (DEC-056 point 2), and its proposals stay data (DEC-056 point 6). It runs in a clone, since the person's checkout may be on another branch. Its brief tells it to propose only, since nothing else holds it to that. A harness loads a name no place ships by that name, so only a copy the commit deploys keeps that definition the commit's.
- **The fallback.** DEC-056 fails closed because a run that is unconfined while it appears confined is worse than none. An unconfined run claims no confinement: the command says what a watched run's fixers run under, and records the form of each run nobody watches (point 4). The person consented to it by starting the run or by turning the switch on. A run refused for a cause of its own shows a fault the person can mend, not the harness's, so it starts in neither form.

**Point 3, the grant.** Before each watched run the command says what the fixers run under, and the person can stop it. So, short of what point 5 leaves open, a grant carries no unconfined run the person does not see start until they turn the switch on. What the switch adds, running with nobody watching, is much the same for every fixer, though a fixer's definition bounds what its unconfined run does (point 5). So one consent covers it, the hold lists the fixers already granted, and the question tells each grant that it reaches runs nobody watches. Words that did not say so carried no consent to those runs, so a grant given under them waits for the person's answer.

**Point 4, the switch.** Unconfined, a run nobody watches may do whatever the project's settings let a session do, with nobody to stop it. A reviewer runs because someone asked for a review. A fixer would start on every merge with nobody asking for it, and what it proposes waits in a queue that is later applied. So whether a project takes that for the loop after a merge is the person's to judge. The rule is decided here and only the choice is the project's, so a setting carries it, and turning it on needs no new record, as the maintainer asked.
- **Held at the merge.** A change of the project's may be an agent's, and an authorisation given up front would carry it with nobody reading it. While the switch is on, a grant also widens what runs with nobody watching. Turning the switch off only narrows what runs, so it needs no hold, and is safe to read from any working tree's own configuration. COR-066 point 4's key is the like case: a key the default branch holds, with its writers named.
- **The reports.** Nobody watched the run, so its faults wait in the queue and in the count line of the command the person runs at each merge.

### Alternatives considered

- **Each run confined, with no fallback, as DEC-056 point 5 decides.** Not taken: the harness the probe tried cannot hold the confined form, so no fixer would start until one can.
- **Runs nobody watches only once the harness confines them.** Not taken: the loop after a merge would wait on the harness. The switch lets the person take the reviewers' form for it, and the confined form takes it over once it holds.
- **Watched runs only, with a later record for runs nobody watches.** Not taken: turning such runs on would need a new record, where the maintainer asked for a setting.
- **A flag that says a person started the run.** Not taken: an agent passes a flag as easily as a person does until a rule denies it to agents, and no rule this capability ships does. With such a rule a flag could hold where a faked terminal does not, so hardening the test may weigh it.
- **A confirmation at the terminal before the fixers start.** Not taken: running the command at a terminal is the request, and the command says what the fixers run under before the first starts.
- **A mode that refuses without asking for runs nobody watches, now.** Not taken here: the record of #3041 weighs it, and its refusal reaches a fixer's unconfined run through [pkit:ADR-066] point 10.
- **A switch for each fixer.** Not taken: what the switch adds is much the same for every fixer, and each grant already names its agent and its types.
- **A switch with three values,** such as one that allows runs nobody watches only in the confined form. Not taken: a confined run needs no consent beyond the grant (point 2), so the switch has only the unconfined form to decide.
- **A fingerprint of a fixer's definition, held with its grant.** Not taken: each release that changes a fixer would stop its runs until the person grants it again, for a change the grant's words do not show. Point 5 states what this leaves open.
- **Superseding DEC-056 whole.** Not taken: its declaration, grants, contract, bounds, queue and confined form stand, so this record overturns only what its Implications name.
