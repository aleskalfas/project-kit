**In plain terms:** the capability supports one platform, macOS, as it supports one browser, Chrome. Its commands run on a Mac, and its drawings are built, checked and looked at there, through Chrome as [visual-communication:DEC-074-supports-chrome-alone] has it and through its other tools as they run on a Mac. No work checks a drawing on Linux, Windows or another platform, or mends a fault only another platform shows. Such a fault is filed and waits. What is already built for another platform is kept as built, such as the places on Linux where the viewing step looks for a browser. A check that runs on another platform all the same, such as the pipeline of the repository the capability is authored in, which draws on Linux, still promises there what the capability computes from a project's files alone, such as a scene and the checks on it, since the same files give it on every machine. What rests on how that platform draws, such as the ink a face draws or a count of pixels, it promises on a Mac alone. On another platform a test of it skips that part, and a pipeline's drawings stand for the platform that drew them. Until a record brings another platform, the capability supports macOS alone.

## Context

[visual-communication:DEC-074-supports-chrome-alone] made Chrome the one browser the capability supports, and left the platform it runs on unbounded. Several accepted records, and the checks of the repository the capability is authored in, reach past a Mac:
- **Runs on Linux.** [visual-communication:DEC-054-html-reads-islands], accepted in the change of [project-kit#3262](https://github.com/aleskalfas/project-kit/issues/3262), asks that before #3262 closes the browser's first read run once on Linux. Earlier records asked for runs on Linux before Tasks that have since closed ([visual-communication:DEC-027-forced-colours-viewing], [visual-communication:DEC-037-text-the-page-hides]).
- **Looks on Windows.** DEC-074 point 1 has a person look on the system a record names, such as Windows for a real forced palette, which Chrome meets only on Windows.
- **Revisits.** Some records are revisited on what a run on Linux, or a real forced palette on Windows, finds ([visual-communication:DEC-015-viewing-step-and-reviewer], [visual-communication:DEC-024-outside-programs-sandbox], DEC-027, [visual-communication:DEC-039-forced-colours-grounds-and-edges]).
- **Checks that draw on Linux.** The pipeline of the repository the capability is authored in runs the test suite, and draws each piece's HTML pages, on a Linux runner through a real Chrome (DEC-024 point 5). DEC-074 point 1 counts the browser a test draws in as a check of Chrome, and Chrome on Linux as Chrome.
- **Where the probes ran.** The probes the records rest on ran on one Mac, such as those of DEC-015, [visual-communication:DEC-020-html-page-drawing], DEC-037, [visual-communication:DEC-045-svg-reads-cover-and-cut] and DEC-054.

Whoever maintains the capability asked: "we need to narrow the assignment same as for browsers. It should run on mac. Once the visual capability will be useful then we can extend it for other platforms." [project-kit#3551](https://github.com/aleskalfas/project-kit/issues/3551), filed on 28 November 2026, asks for the record that writes it down.

Terms:
- A *platform* is the operating system a command of the capability runs on, with each program the command starts there, such as macOS, Linux, Windows, Android or iOS. A *Mac* is a computer of Apple's that runs macOS.
- A platform is *supported* where the capability's commands run on it, its drawings are built for it, checked on it and looked at on it, and each fault it shows is mended, worked around or reported upstream.
- A result *rests on no platform* where the capability computes it from a project's files alone, with no outside program, so that the same files give it on every machine ([visual-communication:DEC-001-visual-communication-discipline] point 8). Such results are a scene and the checks on it ([visual-communication:DEC-005-engine-and-plugins] point 5), validation's answer ([visual-communication:DEC-002-files-and-validation] point 6), and the file a renderer or a code writer writes.
- A result *rests on the platform* where it comes from what a program drew on that platform, or from how a program ran there. Examples are an image's pixels, the ink a face draws, a count or a share of them, the face a browser drew a run in, each read the viewing step takes from them, where the step found its browser, and what stopped it.

## Decision

**The capability supports one platform, macOS. Its commands run on a Mac, and its drawings are built, checked and looked at there. No work checks a drawing on another platform, or mends a fault only another platform shows, and what is built for one is kept as built. A check on another platform promises there what rests on no platform, and nothing that rests on that platform. Until a record brings another platform, the capability supports macOS alone.**

### 1. The capability supports macOS

- **The supported platform** is macOS as Apple ships it, in its current release, on a Mac. There Chrome is the supported browser, as DEC-074 has it, and the capability's other tools are supported as they run on a Mac, such as the SVG renderer's tool and each outside program a command starts (DEC-002 point 8).
- **What it covers.** Each command of the capability, and each program a command starts. Each drawing a check or a person reads: an image of the viewing step and each read taken from it, a probe's drawing, a test that draws, and a person's look or print.
- **Built on a Mac.** Where a form of a file is chosen by how it draws, it is chosen by how it draws on a Mac.
- **What stands as a check of the supported platform.** A check that draws on a Mac: the viewing step, a test, a probe, and a pipeline that draws on a Mac. A check that draws on another platform stands for that platform alone (point 3).
- **Looked at on a Mac.** Where a record asks a person to look, they look on a Mac, in Chrome as shipped (DEC-074 point 1).
- **Chrome in the records.** Where an accepted record names Chrome as the browser a person looks in, or a check stands for, it names Chrome on a Mac. Read so, a record is edited for this only as the Implications say.

### 2. No work checks, looks or mends on another platform

- **No check and no look.** No Task, test, probe or look checks a drawing on another platform, and no Task makes a command run there. A check that runs there all the same, such as a project's pipeline, is read as point 3 says.
- **A fault only another platform shows,** in what rests on that platform, is filed as a bug that names that platform, and waits for the record that brings it. No work mends it meanwhile. That holds of a fault in what a program draws there, and of one in how a command runs there, such as a browser the viewing step does not find. A fault in what rests on no platform is the capability's wherever it shows (point 3).
- **A fault a Mac shows too** is the capability's to mend, work around or report upstream, on whichever platform it was first seen. A run on a Mac tells which it is.
- **A look on another platform** that a record asks for waits for the record that brings that platform, such as a look under a real forced palette.
- **A revisit** an accepted record names, that only a fault, a run or a look on another platform would set off, waits for the record that brings that platform. A revisit on what a look costs in a project's pipeline stands, wherever that pipeline runs, since it bounds the pipeline's time and not what a platform draws. Every other revisit stands.
- **What a probe or a test found on another platform,** in a record's Context or its Rationale, stays as it stood, a fact found on a date.

### 3. A check on another platform promises only what rests on no platform

- **What rests on no platform holds on every platform.** The same files give it on every machine (DEC-001 point 8). So a test of such a result holds on every platform it runs on, as it stands. A failure of it on any platform is the capability's to mend, since that result may not differ between machines.
- **What rests on the platform holds on a Mac alone.** A test whose result rests on the platform, such as the ink a face draws or a count of pixels, promises its full result on a Mac alone. On another platform it asserts only what rests on no platform, and skips the rest, saying why. A failure there that only that platform shows is a fault of point 2.
- **A pipeline's drawings stand for the platform that drew them.** Drawn on a Mac, they check the supported platform. Drawn on another platform, they hold of the supported one only what rests on no platform: the page files, the frames the scene gives, and what the checks found on each scene, at the commit drawn. Their images show each text and shape where the page file places it, and how each is drawn, a text's ink above all, is that platform's. So each read their report takes from the images, an entry or its silence, stands for that platform alone, and so does a stop. Whoever reads them, an agent or a reviewer, takes what rests on the drawing as that platform's, not the supported one's.

### 4. What is built for another platform is kept as built

- **Kept, and checked on no platform.** What the capability holds for another platform stays, such as the places on Linux where the viewing step looks for Chrome and Chromium (DEC-020 point 7), and the stop that tells a browser run as root, as a container on Linux may run it, apart from a sandbox (DEC-024 point 4). No work checks on that platform that it still serves there. The tests that hold it stay, where they rest on no platform.
- **A change to it is like any other.** Where an accepted record decides such a part, changing it needs a record, as any change to what such a record decides does (COR-065 point 3).

### 5. Another platform comes by a record of its own

- **Each further platform** comes by a record that brings it. Until a record brings another platform, the capability supports macOS alone.

## Rationale

**Why one platform.** It is the maintainer's choice: a first version that works, on one platform, before another (Context). Each further platform costs a person's looks there, probes of its own, and the faults only it shows. A text's ink, which the browser's reads count, rests on how each platform draws a face, so each platform would need the reads' plants and their figures checked again. With one platform the work finishes sooner, and the record that brings the next starts from drawings that work.

**Why macOS.** The maintainer named it. Every probe the records rest on ran on a Mac, and a person looks on one. On macOS the permission model keeps a session's sandbox off (DEC-024, Context), so a session there draws a look through the browser itself. So on a Mac what an agent checks and what a person sees agree.

**Why a current release.** Apple ships one current release, and the probes ran on one. An older release would be a further platform to check, with faults of its own.

**Why what rests on no platform still holds everywhere.** The records promise it alike on every machine (DEC-001 point 8, DEC-005 point 5, DEC-002 point 6), and it holds by construction, since no platform enters it. A pipeline on another platform checks it at no cost. A result that differs between machines breaks that promise on a Mac as well, since the next Mac may differ too. Narrowed to a Mac, it would overturn those records and gain nothing.

**Why a test of what rests on the platform skips it elsewhere.** A pass on another platform says how that platform drew, not how a Mac draws, so read as a check it would stand for a drawing the supported platform never made. A failure there would stop a change for a fault no supported reader meets, which point 2 sets to wait. A skip that says why keeps the test in sight, and the part of it that rests on no platform still runs.

**Why a pipeline's drawings stay a way on.** An agent whose session cannot run the browser has no other drawing of the page file (DEC-024 point 4). What rests on no platform holds in them as on a Mac, and each part lies where the page file places it. So they still serve that agent, read as that platform's for how they are drawn. A project that wants them to stand for the supported platform has its pipeline draw on a Mac, which is the project's choice (DEC-024 point 5).

**Why a fault only another platform shows waits, and is not closed.** The maintainer means to extend the capability to other platforms once it is useful (Context). Filed, a fault keeps what was seen for the record that brings its platform. A fault a Mac shows too is a fault of the supported platform, wherever it was first seen.

**Why what is built stays.** Removing a part that serves another platform is work that gains nothing on a Mac. The tests that hold it rest on no platform, so they cost nothing to keep, and the record that brings that platform starts from it. The cost: no work checks the part on its platform, so it may stop serving there unseen.

**Why the records are edited in place.** The decisions README refines a record in place where its decision stands, narrowed, widened or completed. The set of platforms the capability serves was left unbounded, and this record bounds it to macOS, as DEC-074 bounded the browsers. Each clause edited asks for a run or a look on another platform, or counts a check made there as one of the supported platform: DEC-054's run on Linux, DEC-074's look on the system a record names and its checks that stand for Chrome, DEC-024's drawings of a pipeline, and DEC-015's image that stands for one browser. Each narrows with this record, and what its record decides of a page, a read or a way on stands. The edit to DEC-054 removes a run outright, so it was weighed as a partial supersession. Under a top line, its words would stand where a reader of #3262's closing conditions reads them, asking for a run no work makes. So it is edited in place too, with a pointer.

**What it costs.**
- A reader on another platform may meet a fault no work looked for, on Windows, Linux, Android or an iPhone. A project that hands out a page file hands it to them too, so the capability's pages say which platform it supports.
- Chrome meets a real forced palette only on Windows, so no work meets one. The browser's two forced palettes, which the viewing step draws under its flag on a Mac, are the only check of a page under forced colours (DEC-027), and a fault only a real palette shows waits.
- The pipeline of the repository the capability is authored in draws on Linux. Under point 3, its tests check no drawing of the supported platform, and its drawings stand for Linux. A test's full result that rests on the platform runs only where the suite runs on a Mac: a person's run, or the pre-push hook of a clone that opts into it. A builder's run, which the permission model confines, draws no page through the browser (DEC-024 point 6). So a change that breaks a read on a Mac can reach the default branch unseen, until that repository draws on a Mac in its pipeline or a person runs the suite there.
- The drawing tool's test runs in a session whose sandbox is on (DEC-024, Implications). On a Mac the permission model keeps that sandbox off (DEC-024, Context), so the test waits on the model ([project-kit#2839](https://github.com/aleskalfas/project-kit/issues/2839), [project-kit#312](https://github.com/aleskalfas/project-kit/issues/312)).

### Alternatives considered

- **macOS and Linux, since the pipeline draws on Linux.** Not taken: the maintainer named the Mac, and Linux's looks, probes and faults would stay work. What the pipeline checks of what rests on no platform holds on a Mac all the same (point 3).
- **Linux alone, where the pipeline runs.** Rejected: every probe ran on a Mac, and a person looks on one.
- **A test on another platform keeps its full result while it passes there, and is narrowed only once it fails.** Rejected. A pass there says how that platform drew, and a failure stops a change for a fault no supported reader meets. What it would keep is a fault of the reads' own code, which a Mac shows too. A pipeline that draws on a Mac keeps that, and stands for the supported platform.
- **What the records promise alike on every machine, promised on a Mac alone.** Rejected, for the reason above.
- **A pipeline's drawings dropped from the ways on.** Rejected, for the reason above.
- **Support tied to version 1, with another platform in a later version.** Rejected, as DEC-074 rejected it for a browser. A version's number says nothing of which platforms a record has brought, and a record may bring one whenever its work is ready. So the support ends where a record ends it.
- **What serves another platform removed,** such as the places on Linux where the step looks for a browser. Rejected, for the reason above.
- **The look's report names the platform its images were drawn on.** Not decided here. Whoever runs a look knows where it ran, and a project's pipeline says where its runner draws. A Task may add it to the report's form where a reader is found to lack it.
