**In plain terms:** most of what a scene holds on an element describes what an output shows its reader: its place and size, its paints, its text and lines, its picture, its route, that a group is a page, and what a reader who does not see the piece gets. A few properties say something about the element instead: its trace id, where its values came from, which component drew a group, at which version and under which options, and which parts a part lies over on purpose. None describes what an output shows, so no renderer draws them. This record keeps them in one place: one list, in the comparison that finds a renderer's losses before it runs, which names each with the types it may stand on. No renderer names one among what it draws, and none reports a loss of one. The record decides drawing alone: a renderer may still read such a property, write it into its file as a mark a tool reads, or declare that it updates, recreates or reads it back. A property a later change adds takes its side by the same test.

## Context

A renderer declares, for each primitive and property, whether it draws it, updates it in place, recreates it, or reads it back. Before it runs, the capability compares each scene with what it declares it draws, and reports what it cannot take ([visual-communication:DEC-005-engine-and-plugins] point 9). Some properties a scene holds describe nothing an output shows its reader. When this record was drafted, the capability kept them in two places:
- **A group's `component`, `version`, `options` and `page`,** which say which component drew it, at which version and under which options, and that it is a page (DEC-005 point 5; the capability's page on components, "What a scene holds"). Each renderer's declaration listed them under `group`, as properties it draws.
- **An element's `lies-over`,** the parts its part lies over on purpose. [visual-communication:DEC-066-meant-overlaps] point 2 counts it "among what no element draws, beside the element's type, its trace id, its sources and its children", in the code that finds the losses, so that no declaration lists it. Its Rationale, "Why it is no property the element draws", says why, and its Implications leave one rule for both open, for a follow-up to pick "before a third such property copies whichever it finds first". [project-kit#3407](https://github.com/aleskalfas/project-kit/issues/3407) is that follow-up.

The answer meets five things that already hold:
- **A renderer projects the scene,** and reports what it cannot draw as the scene sets it. A format read whole is the one exception: it carries none of the reader's side that the format fixes for it, links aside, and no loss of it is reported ([visual-communication:DEC-001-visual-communication-discipline] point 2, [visual-communication:DEC-033-structure-for-readers] point 9).
- **A reader's tools,** such as a screen reader, read from the file the *reader's side*, what a reader who does not see the piece gets (DEC-033, "Terms").
- **The seam's version** rises only when a plugin must read something differently, and a renderer's own version only when the same input could give another output (DEC-005 points 8 and 9).
- **Every plugin is the capability's** (DEC-005 point 12), so every declaration is too.
- **A renderer may write a mark a tool reads.** When this record was drafted, the SVG renderer wrote each element's trace id into its file, and a group's component and version (the capability's page on outputs, "The SVG renderer").

## Decision

**A property of an element that describes nothing an output shows its reader or gives a reader's tools is one no element draws. The comparison that finds a renderer's losses before it runs holds one list of them, each with the types it may stand on. No renderer names one among what it draws, and none reports a loss of one.**

### 1. What no element draws

- **The test.** A property of an element is *drawn* where it describes what an output shows its reader, or what it gives a reader's tools: its frame, its paints and lengths, its text, its lines and how far they reach, the picture it shows and the places in that picture, its route and its ends, that a group is a page, and the reader's side (DEC-033 point 1). Every other property is one *no element draws*, whatever it says: which element it is, where it and its values came from, which component drew a group, at which version and under which options, or what the owner of the part that drew it says of it to a check, a review or an agent.
- **Drawn first.** The test defines the drawn side, and what no element draws is every other property. So a property that describes what an output shows is drawn, whatever else it says. A list's entries say how a piece's elements fall into groups, and reach a reader's tools, so they are drawn, as a page's regions would be.
- **What it covers.** When this record was drafted: an element's trace id, its sources and its `lies-over`, on an element of any type; and a group's `component`, `version` and `options`.
- **The tree is no property.** An element's type names its primitive, by which a declaration names its entries, and which a renderer that draws no such primitive refuses (DEC-005 point 9). A group's children are the elements it holds, drawn in their order, each compared in its turn. The comparison reads both so, and judges neither as a property, so neither is in the list.
- **By what it describes, not by who reads it.** A drawn property is drawn even where no renderer the capability ships reads it, such as a text's measured height, and each renderer says in its declaration whether it draws it. A property no element draws stays so where a renderer reads it, such as one that writes a group's component into its file as a mark.
- **Of an element.** The scene's root is no element. What a renderer takes of it stays as its records give it, such as a top's physical size ([visual-communication:DEC-034-brand-drawings] point 3).
- **Its source stays its own.** Being one no element draws decides nothing of a property's source: a group's options name where each option's value came from, and `lies-over` names none (DEC-005 point 5, DEC-066 point 2).

### 2. One list, in the comparison that finds the losses, and none of it declared drawn

- **Where it is kept.** The comparison of a scene with a renderer's declaration, which finds what the renderer will lose before it runs (DEC-005 point 9), holds one list of what no element draws. It names each property with the types it may stand on, every type or those that hold it, and passes over each on an element of those types. The page on components names the same properties, under what a scene holds, held equal with the list by a test that joins the two.
- **Drawing alone.** Of what DEC-005 point 9 has a renderer declare of a property, whether it draws it, updates it in place, recreates it or reads it back, this record decides drawing. No renderer names a property of the list among what it draws. Whether it updates one in place, recreates it or reads it back, as a renderer whose medium holds variants of its own might read a group's options back, and how it keeps a field marked as never to be taken back from its medium, its declaration says as that point has it.
- **No loss of it.** No renderer reports a loss of what no element draws, before it runs or as it draws. An output that leaves one out shows its reader all it would show with it, and gives a reader's tools all they would get, so nothing is lost.
- **A mark is no drawing.** A renderer may write a property no element draws into its file as a mark, as one writes an element's trace id, or a group's component and version. A mark serves a tool that finds an element in the file for whoever makes or reviews the piece, such as the viewing step, or one that compares a file's two sides in a review, and no reader's tool reads it. Writing it draws nothing, and leaving it out loses nothing, so a declaration names no mark among what its renderer draws.

### 3. A property a later change adds takes its side by the test

- **No element draws it:** it joins the list, with the types it may stand on, and no renderer names it among what it draws.
- **Drawn:** each renderer that draws it declares it under each type that holds it, and the comparison reports a loss of it for each renderer that does not, as for any drawn property (DEC-005 point 9). A word of the reader's side that the format fixes as left out of a format read whole is the exception: for such a format, no loss of it is reported (DEC-033 point 9).
- **The change that adds it** says which it is, by point 1's test.

## Rationale

**Why one list, and not each declaration.** DEC-066's reason for `lies-over` holds for each property this record covers. Listed in a declaration, a property stands under each type that may hold it, and a renderer added later must list it under each, or report a loss of it in every piece that holds it. A group's `component`, `version` and `options` stand on a group alone, so each declaration listed them once. But the declaration then said that its renderer draws what it does not draw, and a renderer added later would copy that claim, or report a loss that no reader of its output would miss. In the list, each is one entry, in the one place that reads it.

**Why the list names types.** A property that may stand on any element, such as `lies-over`, takes every type, and one that stands on a group alone takes a group. So a name the list holds for one type stays free for a drawn property of another, and the list says no more than the scene holds.

**Why the test is what an output gives its reader.** A renderer reports what it cannot draw as the scene sets it (DEC-001 point 2), and what it draws is what its output gives its reader. So what reaches a reader is what a declaration must say it draws, and nothing else need be. Which properties a renderer reads is that renderer's, and changes as renderers change. A test by it would move a property between the list and the declarations, and a renderer added later that draws by a property no other reads, such as a text's measured height, could not declare it, since the comparison would pass it over. What an output gives its reader does not change with the renderers.

**Why drawing alone.** The four things a renderer declares of a property answer two questions. Whether it draws it is what its output's reader gets, which the test settles. Whether it updates it in place, recreates it or reads it back is how a medium keeps its objects and takes edits back. A medium with components, layouts or variants of its own may keep a property of the list there, such as the variant a group's options chose, and a renderer that reads it back must be able to say so. So the record leaves those three as DEC-005 point 9 has them, and a renderer built for such a medium revisits this record (Implications).

**Why the tree is no property.** The comparison reads an element's type to find its primitive's entry in the declaration, and walks a group's children, comparing each. Each primitive is declared, and each child compared, in its own right, and the children's order is the order in which each is drawn. So the type and the children are compared already, and neither is a property to judge.

**Why a page's mark is drawn.** A page is drawn apart: each renderer draws each page as a page of its own. The mark on a page's group describes that, so each declaration names it under a group, and a renderer added later that cannot draw pages apart reports its loss. The scene's root names its pages too, in order, and renderers draw them from there (the page on components, "What a scene holds"). But the comparison reads no root as an element (point 1), so without the mark no declaration would say whether its renderer draws pages apart.

**Why a text's measured height, an image's picture and the like stay drawn.** A text's measured height and whether it overflows say how far its lines reach. An image's `output`, `file`, `library` and `role` name the picture it shows, wherever it lies, and its exposed points are places in that picture. A line's attached ends name the elements its reader sees it meet, which a medium with connectors of its own draws by (DEC-005 point 5). Each describes what an output shows, though no renderer the capability ships read some of them when this record was drafted. A group's `version` is not of their kind: it names where the component that drew the group came from, and the group's elements describe what an output shows of it.

**Why a mark is no drawing.** A mark such as a trace id lets a tool find an element in a file. What a reader sees, and what a reader's tools read, is the same with or without it. A tool that compares a file's two sides reports a mark that differs to whoever reviews the piece, not to its reader. So leaving one out loses nothing, and a declaration that listed what its renderer marks would claim that it draws it.

### What it costs

- **A judgement at each new property.** The test reads what a property describes, which the change that adds it judges (point 3), and no check can test that. A drawn property misjudged as one no element draws is never compared, so a renderer that cannot draw it reports no loss of it.
- **A declaration says less of the scene.** It names each drawn property, not every property a scene holds. A reader learns what no element draws from the list and from the page on components.

### Alternatives considered

- **Every declaration lists them all as drawn,** `lies-over` under each type. Rejected, for the reason above: each renderer, and each added later, would list under each type what it never draws, or report a loss that no reader misses.
- **One list read for every type alike.** Not taken. A name in it would be taken from every type, so no drawn property of another type could take it later, and a drawn name such as a line's `points` could never join it. A list that names types is one place too.
- **A closed list of what a property may say about an element, every other property drawn.** Rejected: what a property may say of an element is open, and a new kind, such as an owner's word to the review or a note to the agent that translates, would fall to the drawn side, so that every renderer would declare it or report its loss.
- **The list over all four things a renderer declares.** Rejected: a renderer whose medium holds components, layouts or variants of its own could not declare that it keeps or reads back a group's component or options (Rationale, "Why drawing alone").
- **A page's mark in the list,** since the root names the pages too. Rejected: no declaration would then say whether its renderer draws pages apart (Rationale, "Why a page's mark is drawn").
- **The scene keeps them apart, under one key of each element,** beside its sources, which the comparison passes over whole. A reader would see the two kinds in the data. Not taken. It moves keys that the checks, the viewing step and a renderer's marks read, so a renderer that marks one would read differently and the seam's version would rise (DEC-005 point 8). It changes the scene's form for every reader of scenes, for what one entry in one list gives. Its trigger to revisit: a plugin, or a reader outside the capability, that must tell the two kinds apart from the scene alone.
- **Each declaration names what its renderer leaves aside,** beside what it draws. Rejected: every renderer, and each added later, would repeat the same names, the two places this record joins, multiplied by the renderers.
- **The list in the seam,** handed to each plugin with the scene. Not taken: no plugin reads it, and only the capability's comparison does. The seam is what the engine hands its plugins and takes back (DEC-005 point 8).
- **A test by whether a renderer the capability ships reads the property.** Rejected, for the reason above: it moves a property as renderers change, and keeps a renderer added later from declaring what it draws.
- **Each left where it was.** Rejected: two rules, and a third such property would copy whichever it found first.
