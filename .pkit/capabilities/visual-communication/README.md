# visual-communication capability

Visual work made from reusable parts. A *piece*, such as a presentation or a figure in a documentation page, keeps its content as data. Libraries give it its look: components that arrange and draw the content, brands that hold the values (colours, fonts, sizes), and notations that say what a thing is. Several renderers draw the same piece, as a vector picture, a web page or objects on a whiteboard service, and a piece is handed out as a file such as a PDF. A project installs the capability when its visuals should share a look, reuse what was made before, appear under more than one brand or in more than one language, and be checked like the rest of its work.

## What this capability ships

- **The commands** `pkit visual …`, also reachable as `pkit visual-communication …`. Each is described under [Commands](#commands).
- **The file formats,** format 1: a schema for each kind of file a piece, a library or a command writes, under `schemas/`. Each file names its schema in its first lines ([The binding](files.md#the-binding)), so `pkit validate` checks its shape.
- **The foundations library,** under `libraries/foundations/`: a few shared roles, two axes, six colour families, and two top components: `figure`, for a figure, and `deck`, for a presentation ([The foundations](files.md#the-foundations)). Its version is not released yet, so it may change in any release of the capability ([The libraries the capability ships](files.md#the-libraries-the-capability-ships)).
- **The starter library,** under `libraries/starter/`: patterns, such as `layers` and `network`, and blocks, such as `card` and `code`, each experimental. Its README lists them by the question each answers ([The starter](libraries/starter/README.md)). `pkit visual add starter` brings it in, and its version is not released yet either.
- **The neutral brand,** under `libraries/neutral/`: a brand to start from, with a value for every shared role and the fonts it draws in ([The neutral brand](files.md#the-neutral-brand)). It gives no logo. `pkit visual add neutral` brings it in, and its version is not released yet either.
- **Five plugins:** the SVG renderer, which draws the previews and the SVG exports; the PDF renderer, which draws a piece as one PDF for each language and combination of modes; the HTML renderer, which draws a piece's pages as real text over shapes, and whose pages `pkit visual look` draws through a browser; the CSS code writer, which writes a brand out as CSS variables; and the JSON code writer, which writes a brand's resolved values as one JSON document ([Plugins](outputs.md#plugins), [The SVG renderer](outputs.md#the-svg-renderer), [The PDF renderer](outputs.md#the-pdf-renderer), [The HTML renderer](outputs.md#the-html-renderer), [Written code](outputs.md#written-code), [The JSON code writer](outputs.md#the-json-code-writer)).
- **The check,** the `visual-communication:check` member of `pkit validate` ([In `pkit validate`](checks.md#in-pkit-validate)).
- **The agent** `graphic-design-reviewer`, which reads a piece's drawn pages and reports what no check measures ([The reviewer](#the-reviewer)).
- **The skill** `visual-author`, which guides whoever draws a piece, from its first files to pages that read ([Drawing a piece](#drawing-a-piece)).
- **Its operational rules,** the loaded rule set `VIS` in `rule-sets/vis.md` and the file generated from it, `rules.md` ([COR-070](../../decisions/core/COR-070-capability-loaded-rules.md)). Wherever the capability is installed, every session loads `rules.md` ([A capability's rules](../../rules/README.md#a-capabilitys-rules)). Its rules say how an agent goes on where the session's sandbox stops a look ([visual-communication:DEC-024-outside-programs-sandbox] point 6).
- `decisions/DEC-NNN-*.md`: the principles every piece, library and renderer follows.

No notation or producer ships ([Notations](files.md#notations), [Plugins](outputs.md#plugins)). A project writes its own notations, and may write its own brand ([Brands](files.md#brands)). `pkit visual produce` has no producer to run yet, so a piece that declares a produced picture cannot be given one ([Produced pictures](outputs.md#produced-pictures)).

The pages beside this README are the reference:

- [The files of the visual work](files.md): the working folder, the piece, its content, libraries, brands, notations and keys.
- [Components](components.md): a component's file, formulas, layouts and how text is measured.
- [What is made from a piece](outputs.md): renderers, exports, produced pictures and written code.
- [What the check reports](checks.md): every finding, its severity, the findings record and the fingerprint.

## Adopter setup

Install the capability, then sync, so the check's dependencies are in place before `pkit validate` runs it offline ([In `pkit validate`](checks.md#in-pkit-validate)):

```
pkit capabilities install visual-communication
pkit sync
```

The visual work lies in one folder of the repository, the *location*: `visual/` at the top of the repository, unless the project names another. Nothing needs configuring before the first command: the first command that writes there records the location in the capability's configuration. [The location](files.md#the-location) says how it is found and recorded.

Every piece's lock names the foundations ([The lock](files.md#the-lock)), so bring them into the location first:

```
pkit visual add foundations
```

A library the capability ships reaches the location only through [`pkit visual add`](#pkit-visual-add-library). No install, sync or upgrade of the capability writes there, so an upgrade alone changes no piece's look ([What the location holds](files.md#what-the-location-holds)). Run the command again after an upgrade to take the newest released version, and to bring each copy of the library up to date.

## Drawing a piece

The skill `visual-author` walks steps 1 to 6 with you, or with the agent that draws for you. `pkit sync` deploys it with the other skills, in Claude Code as `.claude/skills/visual-author/` ([the Claude Code adapter's README, `deploy-skills.sh`](../../adapters/claude-code/README.md#deploy-skillssh)). Its `piece.md` starts a piece, and its `build-loop.md` renders, checks, reads and mends it until it can stop.

1. **Bring the libraries.** [`pkit visual add <library>`](#pkit-visual-add-library) copies a library the capability ships, such as the foundations, into the location's library folder, and lists it in `libraries/libraries.yaml`. Put each other library version a piece uses there yourself, and list it ([The library folder](files.md#the-library-folder)). A piece needs a brand: bring the neutral brand, or write the project's own ([Brands](files.md#brands)).
2. **Write the piece.** A piece is a folder under `pieces/`: its `piece.yaml` names its libraries, languages, modes and exports, and its content names the components that draw it ([A piece](files.md#a-piece)).
3. **Draw it.** `pkit visual render <piece>` writes the piece's lock, computes its scenes, keeps their findings in `findings.yaml`, and draws an SVG preview of each scene. Open the previews under `.pkit/capabilities/visual-communication/project/local/previews/<piece>/` ([The clone's local folder](files.md#the-clones-local-folder)).
4. **See it.** [`pkit visual look <piece>`](#pkit-visual-look-piece) draws each page as an image, with a report of what the images cannot show ([The viewing step](outputs.md#the-viewing-step)). [The reviewer](#the-reviewer) can read them for you.
5. **Check it.** `pkit visual check <piece>`, or `pkit validate`, reports what the piece breaks ([What the check reports](checks.md)).
6. **Commit the piece's folder:** `piece.yaml`, the content and `findings.yaml` ([The findings record](checks.md#the-findings-record)). The previews stay local to the clone ([The clone's local folder](files.md#the-clones-local-folder)).
7. **Hand it out.** `pkit visual export <piece>` makes a numbered export in each format the piece declares, and records the version in the piece's `exports.yaml`. Commit `exports.yaml`; the exported files stay local until they are handed out ([Exports](outputs.md#exports)). A published piece's export also writes its current copy, the unnumbered files a page links to. Commit that too ([The current copy](outputs.md#the-current-copy)).

A brand's values reach code the same way: a declaration under the location's `code/` folder names the brand and where the code goes, and `pkit visual write-code <name>` writes it ([Written code](outputs.md#written-code)).

## Commands

Every command runs from anywhere in the project: it finds the project root as the nearest folder, from where it runs upwards, that holds the installed capability. `add`, `render`, `produce`, `export`, `mark-final`, `take-up`, `upgrade` and `prune` write in the location, so where none is recorded they take `visual/` and record it, or the path `--location <path>` names ([How a command finds it](files.md#how-a-command-finds-it)). `release` writes in a location that holds the library already, and records none. With `--shipped` it writes in the capability's own folder and `.changes/unreleased/` instead. `look` and `before-after` write only in the clone's local folder, and record no location. A command prints `error: …` and exits 1 when it refuses, or when a write fails. Every check that can refuse runs before its first write, so a refused command has written nothing. Where a write fails, the error names the file the command could not write and why, and the command leaves every file as it was before the run: it removes each file the run made, writes back each file it changed, puts back each folder it replaced or removed, and takes back the location it recorded. It names each file it could not put back. Two commands write before they can refuse. `produce` hands the producer its inputs in the capability's local folder, outside the location, and that hand-over stays as it was written ([Produced pictures](outputs.md#produced-pictures)). `look` holds the fonts it hands its tool in a temporary folder there, which the run removes, and it may leave the local folder itself ([The viewing step](outputs.md#the-viewing-step)). Through a browser it holds the page files and the browser's profile there in the same way ([The HTML renderer's pages](outputs.md#the-html-renderers-pages)).

### `pkit visual status`

Shows where the visual work lies, and each piece with its state and its lock.

- **Prints** the location, and whether the configuration records it or it is the default, not recorded yet. Then each piece under `pieces/`, with its state, whether a draft is pinned, and the version of each library its lock names. A draft with no lock yet says that its first render writes one. A published piece with none says to set it back to a draft for that render. A final piece with none says to write back the lock of the version handed out ([The lock](files.md#the-lock)).
- **Writes** nothing.
- **Exits** 1 when the configuration cannot be read, or records a location that is refused or missing; 0 otherwise.

### `pkit visual add <library>`

Copies a library the capability ships into the location's library folder, lists it, and brings every copy of it up to date.

- **Takes** the newest released version the capability ships ([The libraries the capability ships](files.md#the-libraries-the-capability-ships)). `pkit visual add <library>@<version>` names another released version, and `--being-built` asks for the version being built. Where the library has no released version, it takes the version being built. Asked for the version being built while it carries a released number, it takes that released version.
- **Copies** the version whole into a folder of its own, beside the versions the location holds ([What the location holds](files.md#what-the-location-holds)).
- **Lists it** in `libraries/libraries.yaml`, released with its hash or not released ([The list, `libraries.yaml`](files.md#the-list-librariesyaml)).
- **Brings every copy of the library up to date** in the same run ([What the location holds](files.md#what-the-location-holds)):
  - A copy the list marks not released, of a number the capability ships, is replaced whole by what the capability ships under that number. Where that number is released, the list then marks the copy released ([The list, `libraries.yaml`](files.md#the-list-librariesyaml)).
  - Such a copy is replaced only where every lock that names it is the lock of a draft that is not pinned, which moves at each render, or of a final piece, or you name the lock ([The lock](files.md#the-lock)). Under a pinned draft's lock, a published piece's or written code's, left unnamed, the copy stays as it is. The command names each such piece or declaration, and goes on with the rest of the run. A lock it cannot read counts as one that moves only on purpose, and the command names its file. To tell which locks hold a copy, it reads only a piece's `lock`, `pinned` and `state`, and its record of exports. So a fault in the piece's content stops nothing. A record of exports that cannot be read makes the piece final ([The lock](files.md#the-lock)), so its lock holds no copy.
  - A released copy whose files no longer match its hash is restored as released. One that matches is not written.
  - A copy of a number the installed capability does not ship stays as it is, and so does a version folder the list does not name.
  - A version the list names whose folder is missing is brought in as a copy of its kind is: a released one restored, one not released replaced, under the same locks.
- **Shows a before-and-after** of each lock left on a copy it leaves, so you see what replacing the copy changes:
  - For a pinned draft or a published piece, it draws the piece's scenes with the copy as it is, in `before/`, and with what the capability ships, in `after/`. Both lie under `before-after/<piece>/` in [the clone's local folder](files.md#the-clones-local-folder), each file named as its [preview](outputs.md#previews).
  - For written code, it prints the difference in the code the declaration's writer writes with each ([The declaration](outputs.md#the-declaration)).
  - Where it cannot draw or write a side, as for a fault in the piece's content, it says why and goes on.
- **Replaces the copy once you name each lock left on it.** `--piece <name>` names a pinned draft or a published piece, and `--declaration <name>` a declaration of written code. Each may repeat. Naming it is the move on purpose: the lock keeps its number, and the command writes no `piece.yaml` and no declaration ([The lock](files.md#the-lock), [The declaration](outputs.md#the-declaration)). With any left unnamed, the copy stays, and the command prints the line that names them all. Where a lock on the copy cannot be read, it prints no such line: you mend that lock first.
- **Prints** each copy it writes, as copied, replaced or restored, with each piece and declaration whose lock names it. It calls each piece by its state. Then each copy it leaves, with why, and each lock left with its before-and-after. Where it can read each lock left, it adds the line that replaces the copy. Then each version it lists.
- **Refuses** a library the capability does not ship, naming the ones it ships, and a released version it does not ship. It refuses files the capability ships that no longer match the hash the library's record keeps, or whose files of the capability's format lack their binding ([The binding](files.md#the-binding)). It refuses a hash the list keeps for a released version that differs from the one the capability records, naming both. It refuses a version folder the list does not name, where the version is to be copied, and a library the list names from another source ([The list, `libraries.yaml`](files.md#the-list-librariesyaml)). It refuses a piece or a declaration you name that locks no copy the run would replace, naming what it locks, and one whose lock it cannot read.
- **Exits** 0 when it wrote each copy, or left it with why; 1 when it refused, with nothing written, or a write failed ([Commands](#commands)).

Running it is the consent for each copy it writes. A change the project made in a copy it replaces or restores is lost, as the project's diff shows: a shipped library changes where it is authored, never in a copy.

### `pkit visual release <library>`

Releases a version of a project's own library, after it reads the version in full and compares it with the library's previous release.

- **Takes** the newest version the library folder holds of a library the list names from the source `project`, listed `released: false`.
- **Reads it in full,** and names each finding that refuses the release ([What each run judges](checks.md#what-each-run-judges)).
- **Compares it** with the library's previous release, and prints what it finds ([What a release compares](files.md#what-a-release-compares)).
- **Writes** the release the version needs into its `library.yaml` ([`library.yaml`](files.md#libraryyaml)), then lists the version released ([The list, `libraries.yaml`](files.md#the-list-librariesyaml)). It writes nothing else.
- **Refuses** a version the list does not name, one released already, and a library the project does not own: one the capability ships, or one another repository shares.
- **Exits** 0 when it released the version; 1 when it refused, with nothing written, or a write failed ([Commands](#commands)).

Before you release a library for other projects, sync from a tagged install of the methodology. Then the release the version needs covers what it uses ([`library.yaml`](files.md#libraryyaml)). The advice does not apply where the capability is authored, since no sync copies into that tree.

`pkit visual release <library> --shipped` releases the version being built of a library the capability ships, where the capability is authored. It reads and compares the version the same way. Each condition it holds the version to, and each file it writes, is under [The libraries the capability ships](files.md#the-libraries-the-capability-ships). Among the files it writes is a patch changeset for the capability: raise its kind where the release needs more.

### `pkit visual render <piece>`

Draws a piece in each of its languages and each combination of modes it names.

- **Moves the lock** of a draft and writes it into `piece.yaml`. It only checks the lock of a pinned draft, a final piece or a published piece, and a refusal of a final or a published piece's lock says its state ([The lock](files.md#the-lock)).
- **States** the facts of the lock's move ([The lock](files.md#the-lock)), which no `findings.yaml` keeps ([Content against components](checks.md#content-against-components)).
- **Computes every scene,** or refuses where a font cannot measure the text ([How the engine computes a scene](components.md#how-the-engine-computes-a-scene)).
- **Writes `findings.yaml`** beside `piece.yaml` ([The findings record](checks.md#the-findings-record)).
- **Draws the previews** with the SVG renderer, and replaces the piece's previews from before ([Previews](outputs.md#previews)).
- **Prints** the lock, the facts it states, each finding, and each loss the renderer reports that the piece does not accept ([Accepting a loss](outputs.md#accepting-a-loss)).
- **Prints after `preview:`** each stand-in a preview shows, with why ([The facts of an export](components.md#the-facts-of-an-export)). It also prints what a fact's real text finds in a preview, which no `findings.yaml` keeps.
- **Of a final piece,** it writes no `findings.yaml`, and one left from before stays ([The findings record](checks.md#the-findings-record)). It still draws the previews and prints what it finds.
- **Exits** 0 when it drew the piece, findings or not; 1 when it refused, with nothing written, or a write failed ([Commands](#commands)).

### `pkit visual check [<piece>]`

Checks every piece of the location, or the one named, without drawing anything.

- **Reads** the location, or the piece named, and judges each part in turn ([What each run judges](checks.md#what-each-run-judges)). It reads a piece's scenes from its findings record where it can ([When the check reads it](checks.md#when-the-check-reads-it)).
- **Prints** a summary, then each finding with its severity ([What a finding says](checks.md#what-a-finding-says)). `--json` prints the findings document `pkit validate` reads.
- **Writes** nothing, and runs offline ([In `pkit validate`](checks.md#in-pkit-validate)).
- **Exits** 1 when a finding fails; 0 otherwise. With `--json` it always exits 0, as `pkit validate` requires.

### `pkit visual produce <piece> <output>`

Runs the producer a piece declares for one of its produced outputs, and keeps its picture.

- **Works out the variants** the producer makes ([Variants](outputs.md#variants)), and hands it their values ([The hand-over](outputs.md#the-hand-over)).
- **Keeps the picture** only when no input changed during the run and every variant is a PNG of the declared pixel size, exposing the same points. Then it writes each variant and the record in the piece's folder, under `produced/<output>/`, and removes a variant file left from before.
- **Prints** each loss the producer reports that the piece does not accept ([Accepting a loss](outputs.md#accepting-a-loss)).
- **Refuses** a final piece, and a piece with no lock yet. For a draft, run `pkit visual render <piece>` first. Set a published piece back to a draft for its first render ([The lock](files.md#the-lock)). Before it runs, it refuses a producer it cannot run here ([Plugins](outputs.md#plugins)). What a producer is handed and returns is under [Produced pictures](outputs.md#produced-pictures).
- **Exits** 0 when it wrote the variants and their record; 1 when it refused, with nothing written in the location, or a write failed ([Commands](#commands)).

### `pkit visual export <piece>`

Makes a numbered export of a piece in each format it declares.

- **Makes the run's files,** each under the piece's next version number, in the clone's local folder ([Exports](outputs.md#exports)).
- **Keeps a published piece's current copy,** replacing it whole in the piece's folder, or writing it at the place the piece names, and naming each file it leaves behind ([The current copy](outputs.md#the-current-copy)).
- **Records the version** in `exports.yaml`, and the version that wrote a current copy ([The record of exports](outputs.md#the-record-of-exports)).
- **Uses the lock** `piece.yaml` holds, and never moves it.
- **Refuses** a final piece, which takes no export, and names [`pkit visual take-up`](#pkit-visual-take-up-piece-name), which copies it for new work. It refuses a published piece whose lock differs from the one its current copy was made under. It refuses for each other reason under [What refuses an export](outputs.md#what-refuses-an-export). `--use-stale <output>` takes a stale picture as it is, and may repeat.
- **Exits** 0 when it exported and recorded the version; 1 when it refused, with nothing written, or a write failed ([Commands](#commands)).

### `pkit visual mark-final <piece> <version>`

Marks a piece final, and names the version handed out, whatever changed since ([The lock](files.md#the-lock)).

- **Puts back the lock** that version was made under, and names it. It puts back nothing else.
- **Says what else changed,** each input that still does not verify, and stops on none of it.
- **Says what no longer holds of the lock,** and goes on.
- **Moves every file of the version** from the clone's local folder into `handed-out/`, in the piece's folder. Commit them with the piece.
- **Names the version** in `exports.yaml` ([The record of exports](outputs.md#the-record-of-exports)).
- **Says so** where the version named did not write the piece's [current copy](outputs.md#the-current-copy), which stays.
- **Refuses** a version with a file missing or changed, naming each, one with a fingerprint it cannot read, and a second version on a piece that has one handed out.
- **Exits** 0 when it marked the piece, whatever it said; 1 when it refused, with nothing written, or a write failed ([Commands](#commands)); 2 on a usage error.

### `pkit visual take-up <piece> <name>`

Takes a final piece up again, as a new piece copied from it: a draft with its lock pinned ([The lock](files.md#the-lock)).

- **Takes** a piece with a version handed out, and a name no piece of the location holds.
- **Copies** the piece's folder whole into `pieces/<name>/`, but for what only its past holds: `exports.yaml`, `findings.yaml`, `handed-out/` and `current-copy/`.
- **Writes the new `piece.yaml`** as the final piece's, with `state: draft`, `pinned: true` and the lock of the version handed out, and without `copy-place`. Every other byte stays.
- **Prints** the lock it pinned, and each input that changed since that version, which the copy holds as it stands. Then it names the new piece: commit its folder.
- **Leaves** the final piece as it was.
- **Refuses** a piece with no version handed out, as a piece set final by hand is, and a name taken or not a piece's name. It refuses a version whose lock it cannot read, and a file it copies or writes that is reached through a link.
- **Exits** 0 when it copied the piece; 1 when it refused, with nothing written, or a write failed, leaving no part of it ([Commands](#commands)); 2 on a usage error.

### `pkit visual look <piece>`

Draws a piece's pages as images, for a person or an agent to read ([The viewing step](outputs.md#the-viewing-step)).

- **Draws** every page in the source language, unless flags pick others.
- **Reads** a piece that declares `html` through the HTML renderer, and any other through the SVG renderer. `--renderer svg` or `--renderer html` names one.
- **Needs a browser** for the HTML renderer's pages, which no other format needs. The capability installs none ([The HTML renderer's pages](outputs.md#the-html-renderers-pages)).
- **Writes** each image and its frames, and one report, in its renderer's folder, replacing what an earlier run left there. Through the HTML renderer it writes each page file too ([What a run writes](outputs.md#what-a-run-writes)).
- **Prints** the lock, the renderer and what the report says ([What the report says](outputs.md#what-the-report-says)), then each stand-in an image shows, with why ([The viewing step](outputs.md#the-viewing-step)).
- **Uses the lock** `piece.yaml` holds, and never moves it.
- **Refuses** for each reason under [What refuses a run](outputs.md#what-refuses-a-run).
- **Exits** 0 when it drew, whatever the report says. It exits 1 when it refused, with its renderer's folder left as it was, or when a write failed ([Commands](#commands)). It exits 2 on a usage error. It exits 3 when the browser stopped, leaving the page files and a report, and no image ([When the browser stops](outputs.md#when-the-browser-stops)).
- **Names the ways on** where it stops, in this order: a build pipeline's drawings, where the project has its pipeline draw them ([A pipeline's drawings](outputs.md#a-pipelines-drawings)); the same look, run once by a person outside any sandbox; and the SVG renderer's pages.

### `pkit visual pages <piece>`

Lists what [`pkit visual look`](#pkit-visual-look-piece) can draw of a piece.

- **Prints** the piece's languages and keys, what it draws by default, and each page by its number and trace id. Then the renderer it reads by default, and each renderer's tool. `--json` prints it as one document.
- **Finds the browser** a run would start, and starts none. It names the program, or where it looked where it found none.
- **Writes** nothing.
- **Exits** 0 when it listed; 1 when the piece cannot be drawn, such as with no lock yet or a lock that does not hold. It exits 1 too where the configuration's `browser` names no path ([The browser](files.md#the-browser)).

### `pkit visual before-after <piece>`

Draws each of a piece's pages under two locks, and prints each page that differs. You ask for one of two looks.

- **`--ahead` looks ahead, before a move of the lock.** The before is the lock of the version that wrote a published piece's [current copy](outputs.md#the-current-copy), and otherwise the lock the piece holds. The after is the newest released versions that fit, within the lock's majors. It prints each newer version it did not take, with why.
- **`<library>@<version>` names versions for the after,** in the form `pkit visual add` takes, and may repeat. The after then moves what you name, and only what that needs. It prints each clash or lost end a version named goes past.
- **Who takes a look ahead** ([The lock](files.md#the-lock)):
  - A published piece, whose names must be released versions.
  - A draft, only with versions named, which may be versions not yet released.
  - A final piece, with none named. Its two locks are one.
- **`--back` looks back, at a change.** The base is where your branch left the default branch, or the branch `--base <ref>` names. The before is the lock of the version that wrote the copy at that commit, or the lock held there where no version did. The after is the lock the piece holds now. A piece the base does not hold has no before, and the command says so.
- **Draws** both sides with today's engine, from the piece's files and [produced pictures](outputs.md#produced-pictures) as they lie, and it runs no program. Both sides fill what a piece shows of its export in one way, as a preview does, so a number the piece shows does not differ ([The facts of an export](components.md#the-facts-of-an-export)).
- **Writes** each page in `before/` and `after/`, under `before-after/<piece>/` in [the clone's local folder](files.md#the-clones-local-folder), each file named as its [preview](outputs.md#previews). It replaces what an earlier run left there, and writes nothing else.
- **Prints** each lock, each page that differs, and each picture that is stale or missing. It says where the two locks are one, and where the engine's release differs from the one the copy's version recorded. Last, it prints each stand-in the sides show, with why ([The facts of an export](components.md#the-facts-of-an-export)).
- **Goes on** past a drawing it cannot make, such as where a library version left the project. It says why, and draws the other side.
- **Refuses** a piece with no lock yet, a draft with no version named, and a final piece with one. It refuses a version a move cannot take, and a base that resolves to nothing.
- **Exits** 0 when it drew a side or said why not; 1 when it refused, with nothing written, or a write failed ([Commands](#commands)); 2 on a usage error.

### `pkit visual upgrade <piece>`

Proposes a move of a published piece's lock, as a diff in the working tree ([The lock](files.md#the-lock)).

- **Takes** a published piece, and reads the lock its `piece.yaml` holds, whoever wrote it. It refuses any other piece, and names what moves that lock.
- **Moves the lock** to the newest released versions that fit, within the lock's majors. It prints each newer version it did not take, with why.
- **`<library>@<version>` names versions instead,** in the form `pkit visual add` takes, and may repeat. The run then moves what you name, and only what that needs.
- **Looks ahead** as [`pkit visual before-after --ahead`](#pkit-visual-before-after-piece) does, and prints each page that differs. The drawing lies in [the clone's local folder](files.md#the-clones-local-folder).
- **Writes,** as one change, the lock, the findings record, a new version and the current copy. It draws no preview.
- **Commits nothing,** and makes no branch. Land the diff as you land any change, or discard it.
- **Says so and writes nothing** where nothing moves.
- **Stops** on an edit since the copy and on a stale picture, and prints the line that goes on. `--edited <input>` names an input that changed, and `--use-stale <output>` a picture to use as it is. Each may repeat.
- **Says** where no file of the copy stood, so the change shows only an after, and names each file it leaves behind ([The current copy](outputs.md#the-current-copy)).
- **Names** each finding that fails under the moved lock, and stops on none of them.
- **`--dry-run`** stops where the run would, says what it would write, and prints each page that differs. It keeps no drawing: a temporary folder in the clone's local folder holds it, and the run removes that folder.
- **Refuses** what the search refuses, a fingerprint it cannot read, and whatever refuses an export but a lock that differs ([What refuses an export](outputs.md#what-refuses-an-export)).
- **Exits** 0 when it proposed the move, found nothing to move, or ended a dry run; 1 when it refused, with nothing written, or a write failed ([Commands](#commands)); 2 on a usage error.

### `pkit visual outdated`

Lists what each lock a person moves could still take, across majors ([The lock](files.md#the-lock)).

- **Takes** each lock a person moves: a published piece's, a pinned draft's and written code's. An unpinned draft's render moves its own lock, and a final piece's never moves, so both are left out.
- **Names,** for each library a lock names, the version the lock names and the newest that fits within its major. A published piece's lock takes released versions alone, and a lock a hand moves takes every version.
- **Names each other newer version,** with why a move would not take it: a later major, a clash, a lost end, or a version the installed capability cannot read.
- **Says** what moves each lock that is behind: [`pkit visual upgrade`](#pkit-visual-upgrade-piece) for a published piece, and a hand for a pinned draft or written code.
- **Says so** where no lock is behind, and names each lock it could not judge, with why.
- **Writes** nothing, and needs no network.
- **Exits** 0 when it listed the locks, whatever is behind; 1 when the location cannot be read ([Commands](#commands)).
### `pkit visual prune`

Removes each library version that lies behind, with its entry in the list, once it has shown its list and asked ([A version that lies behind](files.md#a-version-that-lies-behind)).

- **Prints its list first:** each version it would remove, with the newer one that serves in its place, and each version it spares, with why. Then each kept export made under a version it would remove, and each kept export whose lock it cannot read.
- **`--dry-run`** prints that list, and removes nothing.
- **Asks** a terminal once whether to remove the versions listed. `--yes` gives that consent up front. With no terminal and no `--yes`, it refuses and removes nothing.
- **Removes** each version's folder, and its entry in `libraries/libraries.yaml`, from the working tree alone. It stages nothing: land the removal as a change of its own. It prints each version it removed, and how to bring one back.
- **Says so** where no version lies behind.
- **Stops,** removing nothing and naming the file, on a lock it cannot read, a record of exports it cannot read, or a fingerprint it cannot read of the version that wrote a current copy ([The record of exports](outputs.md#the-record-of-exports)). It stops on a list it cannot read, or whose text cannot lose an entry ([The list, `libraries.yaml`](files.md#the-list-librariesyaml)).
- **Exits** 0 when it removed what lies behind, found nothing to remove, ended a dry run, or was answered no; 1 when it stopped or refused, with nothing removed, or a removal failed ([Commands](#commands)); 2 on a usage error.

### `pkit visual write-code <name>`

Writes a brand out as code, as the declaration `code/<name>.yaml` in the location asks.

- **Writes** the code to the declaration's `out`, and its record beside it ([The record beside the code](outputs.md#the-record-beside-the-code)). Where the record verifies and the code is what the writer writes now, it writes nothing and says the code is up to date.
- **Never moves** the declaration's lock ([The declaration](outputs.md#the-declaration)).
- **Prints** each loss of the writer that the declaration does not accept ([Accepting a loss](outputs.md#accepting-a-loss)).
- **Exits** 0 when it wrote the code or found it up to date; 1 when it refused, or a write failed ([Commands](#commands)); 2 on a usage error.

## The reviewer

`graphic-design-reviewer` is the capability's agent. It looks at a piece's pages as they were drawn, and reports what no check measures, such as a text over a picture. The adapter deploys it as it deploys any agent ([Deploy mechanics](../../agents/README.md#deploy-mechanics)).

To use it:

1. **Draw the pages.** Run [`pkit visual look <piece>`](#pkit-visual-look-piece), with the pages, languages, modes and renderer you want read. The reviewer runs no command, so it sees only what that run drew.
2. **Dispatch it,** naming the piece. It reads the images in the folder of the renderer that drew them, with the frames and the report beside them, and the piece and the brand. You may hand it other images of the same pages, from another tool or renderer, and it says which drew each. It changes nothing.
3. **Read its report.** It opens with the pages, languages and modes it looked at, and names what it did not see. What it did not see is not looked at, never clean.

Where a run's folder holds a report and no image, the browser stopped. The reviewer says so, and looks at nothing ([When the browser stops](outputs.md#when-the-browser-stops)). It passes on to you the ways on the stop names, in their order.

You may hand it a build pipeline's drawings instead, fetched into a folder of their own ([A pipeline's drawings](outputs.md#a-pipelines-drawings)). It names those images as drawn by the pipeline, at the commit it drew.

Each finding names the page, and the element's trace id where the element was drawn ([Trace ids](components.md#trace-ids)). A finding is one of two kinds:

- **A fault,** which the agent's list names: a part missing or blank, a wrong font, text over text, a text that does not read over a picture, a wrong picture, an overlap, a fault of alignment, or a drawing that disagrees with a passing check.
- **A note,** anything else worth a look.

Its findings are advice. They join no validation and hold no merge.

It needs a harness that reads images. Where the harness reads none, it stops and says so, and reports nothing as looked at.

## Citing this capability's decisions

Inside this capability's own content, cite decisions by their filename
stem: `[visual-communication:DEC-001-<slug>]`. Other capabilities and adopter content
use the same form.

## Dependencies

No other capability. The commands run their scripts through `uv`, with the Python packages each script pins; `pkit sync` installs those of the check, so `pkit validate` runs it offline. It installs those of `pkit visual pages` too, which pins every package `pkit visual look` does, so that command draws with no network. The HTML renderer's pages need a browser of the Chromium family besides, which the capability does not install ([The HTML renderer's pages](outputs.md#the-html-renderers-pages)).
